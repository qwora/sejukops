## What was checked

### Module 1 — Admin order submission
- Order number generated by the database and sequential (ORDER1272 → ORDER1273).
- All required fields saved; phone stored as `60…` for WhatsApp.
- Validation: missing name, invalid phone, unknown service type, negative price are rejected.
- Only admin can create orders (technician and manager get 403).
- Bonus: order summary page after creating; WhatsApp "new job" message to the technician.
- AI "Fill from a document": message → name, phone, address, service, branch, problem, price, date ("esok 11 pagi" → tomorrow 11:00).

### Module 2 — Technician job
- Start → complete on a phone-size screen; two photos and a receipt uploaded to Supabase Storage and visible to the manager.
- Final amount = quote + extras, recalculated on the server (a fake client total of 99,999 was ignored).
- More than 6 files rejected; files from another order rejected; empty work done rejected.
- Only the assigned technician can start or complete; duplicate submission blocked.
- Decline with a reason → order back to New, unassigned, admin notified. Decline without a reason rejected; decline after starting rejected.
- Bonus: payment amount, method and receipt photo; feedback message; manager notified.

### Module 3 — WhatsApp trigger
- Job Done creates the customer message in the same server request, word for word from the brief:
  *Hi QA Final Test, Job ORDER1272 has been completed by Technician John at 22:18 on 27 Oct. Please check and leave feedback. Thank you!*
- Deep link `https://wa.me/60123004100?text=…` targets the customer; "Send on WhatsApp" marks it sent and logs it.

### Manager review and rules
- Manager return (with note) → technician notified → resubmits → manager approves → order closed.
- One review record per order (a second review updates it).
- Admin cannot approve, technician cannot approve or close, closed orders cannot be reassigned.
- Activity log has every step with the person who did it:
  `order_created → reschedule → assign → start → complete → whatsapp_sent → return → complete → approve → close`.

### KPI dashboard
- Jobs, revenue, reschedules, leaderboard and branch figures match direct database queries.
- Reschedule action increases the postpone/reschedule count.

### AI operations assistant
Supported, answered from filtered records: jobs by technician (last week / today), top technician, jobs completed today, overloaded technicians, waiting for review, unassigned orders, flagged jobs, extra charges above RM 100, monthly revenue, a question in Malay.
Refused with a fixed message: "What is the weather in KL?", "Delete all orders". Technicians cannot use it (403).

## Bugs found and fixed

| # | Problem | Fix |
| --- | --- | --- |
| 1 | A viewer whose computer is not on Malaysia time saved slots an hour off (11:00 typed → 10:00 saved). | Date-time fields are always read and shown as Malaysia time, labelled "Malaysia time". |
| 2 | AI supervisor said "check before approving" for a job only RM 20 above the typical price, and once wrote "has been approved". | Verdict is now rule-based (medium/high flag or > 1.5× typical price); the AI only explains it, as a suggestion. |
| 3 | "Continue as…" logged a red 404 in the console when reviewer accounts are not set up. | The check now answers quietly and falls back to demo mode. |
| 4 | Negative price showed "Please fill in: quoted price". | Now "Quoted price can't be negative." |
| 5 | Job done screen did not mention the receipt photo. | Shows "· receipt attached". |

## Not covered / known limits

- **Real reviewer accounts:** not set up yet, so "Continue as…" uses demo mode. Signup with a new email was not tested, to avoid creating accounts.
- **Reschedule KPI** counts reschedules on jobs scheduled within the period, not by the date the reschedule happened.
